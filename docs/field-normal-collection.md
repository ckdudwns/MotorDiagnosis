# 실제 정상 데이터 수집·보관 준비

## 범위와 현재 한계

이 도구는 **이미 수신해 저장한 진동 기본 특징 21개**를 읽기 전용으로 보관하고, 사람이 정상이라고 확인한 기록을 조정용·평가용으로 나눕니다. 실제 보드를 운전하거나 데이터를 새로 측정하지 않으며 모델 재학습·임계값 변경·운영 배포도 수행하지 않습니다.

- 입력: `mcc5-vibration-800hz-xyz-v1`, 800Hz, XYZ, 각 축 512개/640ms, 단위 g, 기본 특징 21개.
- 기존 4개 요약 특징이나 음향은 이 입력을 대신할 수 없습니다.
- **21개로 66개 후보의 추가 스펙트럼 특징을 복원할 수 없습니다.** 66개 후보의 현장 조정에는 동일 구간의 원시 XYZ를 별도 보존하거나 검증된 추가 특징 계산·저장 경로가 필요합니다. 이 도구는 항상 `spectral66Ready: false`를 표시합니다.
- 수집 검사 통과는 센서 교정, 정상 판정의 진위 또는 현장 정확도 인증이 아닙니다. `fieldValidated`는 항상 false입니다.

Graphify의 기존 그래프는 과거 데이터 내보내기 경로 탐색에만 사용했습니다. 현재 연속 구간 저장 구조는 실제 `vibration_windows` 소스로 확인했습니다.

## 1. 담당자가 기록할 내용

아래 명령은 **해당 코드가 반영된 저장소의 루트**에서 실행합니다. 서버 배포가 자동으로 수행된 것은 아닙니다.

```bash
.venv/bin/python -m ai.ai1.mcc5_training.field_collection template --output session-a.json
```

빈 파일을 편집해 다음을 실제 확인값으로 채웁니다. 비밀번호·수집 토큰을 넣지 마세요.

| 항목 | 기입 기준 |
| --- | --- |
| sessionId | 보관 파일의 고유 이름 |
| collectionRunId | 독립된 실제 운전·수집 기록 ID. 한 기록을 파일로 나눠도 같은 ID 유지 |
| conditionId / operatingCondition | 동일 운전 조건을 식별할 ID와 회전·부하·정상 운전 상태 설명. 실제로 모르는 RPM은 추정해 기입하지 않음 |
| deviceId / siteId / assetId | 수집 당시 실제 장치·사이트·설비 매핑 |
| start / end | 측정 구간 시작과 끝. 시간대 포함 ISO 시각, 예: `2026-09-07T10:00:00+09:00` |
| firmwareVersion | 실제 실행 펌웨어 버전 또는 커밋 |
| mountingDescription / axisMapping | 실제 부착 위치·고정 방법·XYZ 방향 |
| gConversionEvidence | ADXL345 레지스터 값 → g 변환 설정과 확인 근거. mm/s 교정으로 간주하지 않음 |
| normalReview | 담당자, 확인 시각, 독립된 정상 확인 근거. 모델이 정상이라고 판정한 결과를 근거로 사용하지 않음 |

`normalReview.status`는 미확인 `pending`, 확인 후 `confirmed_normal`, 부적합 `rejected` 중 하나입니다. 정상 확인 전에도 보관은 가능하지만 조정·평가 계획에는 포함되지 않습니다. 확인 근거 없이 상태만 바꾸지 마세요.

`qualityLimits`는 수집 전에 합의합니다.

- `minimumValidSeconds: 300`: 초기 점검용 유효 5분 목표일 뿐, 최종 학습 분량 또는 통계적 충분성을 뜻하지 않습니다.
- `maxMissingWindows: 0`, `maxInvalidWindows: 0`: 초기 엄격 검사 기본값. 실패 결과를 통과시키려고 사후에 완화하지 않습니다.
- `maxTimingErrorUs: null`: **미정 상태이므로 검사 통과 불가**. 장치 담당자와 허용 오차를 정한 뒤 정수 마이크로초로 입력합니다.

장비가 승인한 안전한 운전 범위에서만 수집하세요. 고장을 인위적으로 만들거나 안전장치를 해제하는 절차는 포함하지 않습니다. 동일 조건을 여러 독립 기록으로 확보하고, 한 부팅 기록 안에서 세션을 구성합니다. 조건·부착·축·펌웨어가 달라지면 별도 기록으로 관리합니다.

## 2. 저장 DB에서 전체 구간 보관

최근 100개만 반환하는 화면/API를 장시간 수집본으로 사용하지 않습니다. 연속 구간 저장 기능이 배포되어 실제 21개 기록이 저장된 후, 해당 DB를 읽을 권한이 있는 서비스 계정으로 실행합니다.

`VIBRATION_WINDOW_DB_PATH` 설정을 확인하세요. 현재 코드의 기본 상대 경로는 `output/vibration-windows.sqlite3`이며, 서비스 작업 디렉터리에 따라 실제 절대 경로가 달라집니다. DB가 없으면 도구는 새 DB를 만들지 않고 중단합니다.

```bash
.venv/bin/python -m ai.ai1.mcc5_training.field_collection export \
  --database /home/ubuntu/MotorDiagnosis/output/vibration-windows.sqlite3 \
  --session session-a.json \
  --output field-archives/session-a

.venv/bin/python -m ai.ai1.mcc5_training.field_collection check \
  --archive field-archives/session-a
```

현재 연속 구간 저장 코드는 2일 보존 및 행 수 제한이 있으므로 삭제되기 전에 내보내야 합니다. 한 번에 최대 6시간·10만 구간으로 제한합니다. SQLite 읽기 트랜잭션은 스냅샷을 유지하지만 긴 읽기가 운영 DB의 체크포인트에 영향을 줄 수 있으므로 초기에는 짧은 구간으로 확인합니다.

출력은 `session.json`(메타데이터), `windows.ndjson`(측정 구간), `audit.json`(검사·SHA-256)입니다. 원본 DB는 수정하지 않으며 기존 출력 디렉터리는 덮어쓰지 않습니다. 중단되어 `audit.json`이 없는 부분 출력은 완료된 수집본이 아닙니다. 원인을 확인하고 새 출력 경로로 다시 실행하세요.

검사는 장치 범위·특징 형식·숫자·품질·누락·중복·순번·시간 간격과 사람의 정상 확인 여부를 확인합니다. 불량 구간은 기록에 남기며 정상 특징으로 채우지 않습니다. `check`는 파일 해시와 내용을 다시 검사합니다. 해시는 우발적 변경 감지용이며 담당자의 서명·진위 보증은 아닙니다.

`maxAdjacentTimingErrorUs`는 장치가 기록한 구간 시작 uptime 간격 검사입니다. **실제 800Hz 샘플 클록이나 센서 FIFO 손실을 독립 측정한 값이 아닙니다.** 시각의 초 단위 표현은 허용하며 요청 구간 경계에는 한 구간의 위상 불확실성이 있습니다. 정밀 품질 시험은 별도로 필요합니다.

보관 후 메타데이터를 직접 고치면 해시 검사에 실패합니다. 검토 완료본은 원본 DB가 보존되어 있을 때 수정된 세션 명세로 새 디렉터리에 내보내고, 이전 보관본도 별도 이력으로 유지하세요.

## 3. 조정용·평가용 분리 계획

같은 장치·부착·축·펌웨어·변환 근거·운전 조건마다 최소 2개의 독립 `collectionRunId`가 필요합니다. 이는 분리 가능한 구조적 최소치이며 충분한 데이터 양을 보증하지 않습니다.

```bash
.venv/bin/python -m ai.ai1.mcc5_training.field_collection build \
  --sessions field-archives/session-a field-archives/session-b \
  --output field-collections/normal-pilot-v1
```

전체 운전 기록 단위로 약 25%(최소 1개, 올림)를 평가용으로 남기고 나머지를 조정용으로 배정합니다. 기본 seed는 42이며 특징값이나 모델 점수를 보고 배정하지 않습니다. 같은 실제 기록을 다른 run ID로 속이지 않았는지는 담당자가 확인해야 합니다. 겹치는 장치·부팅·순번, 중복 세션, 품질 미통과 및 수정된 보관본은 거부합니다.

생성되는 `collection.json`은 **분리 계획**이지 학습 모델이 아닙니다. 이 계획을 확정한 뒤 평가 기록을 보며 특징·임계값을 반복 조정하지 마세요. 새 기록 추가나 seed 변경으로 유리한 평가 묶음을 고르는 것도 금지합니다. 기록 파일을 이동한 경우 계획의 경로도 달라지므로 원래 보관 경로를 유지하는 것이 좋습니다.

## 완료 기준

1. 실제 21개 구간이 연속 저장되고 초기 보관·품질 검사가 통과한다.
2. 독립적인 정상 확인과 조건별 반복 기록이 확보된다.
3. 조정용·평가용 기록을 분리해 고정한다.
4. 사용할 모델의 입력과 수집 데이터가 일치한다. 66개 후보는 추가 수집 경로 없이는 이 단계 미완료다.
5. 조정 후 잠가 둔 정상 평가본으로 오탐을 확인하고, 별도의 이상 데이터로 탐지율도 확인한다.

현재 구현·합성 회귀 테스트만으로 실제 수집 완료, 오탐 감소 또는 현장 검증 완료를 선언하지 않습니다.
