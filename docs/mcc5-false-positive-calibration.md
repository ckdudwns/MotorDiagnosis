# MCC5 오탐 감소: 정상 운전 조건별 임계값 조정

## 결론

2026-09-07 RF66의 임계값 조정 방식을 비교했다. 오탐을 낮출 수 있었지만 탐지율 손실 및 최악 조건 오탐이 커 **후보 선택 없음**, 운영 적용 보류다. 모델 파일이나 운영 임계값을 교체하지 않았다.

아래는 같은 모델·평가 구간을 사용한 8개 train 운전 조건 분리 검증의 평균이다.

| 조정 방식 | 평균 오탐률 | 평균 탐지율 | 최악 조건 오탐률 | 평균 균형 정확도 |
| --- | ---: | ---: | ---: | ---: |
| 정상 조건 1개 q99, 대조군 | 12.05% | 82.55% | 59.29% | 85.25% |
| 정상 조건 2개 통합 q99 | 4.20% | 75.30% | 18.57% | 85.55% |
| 조건별 q99 중 높은 값 | 3.75% | 73.24% | 15.00% | 84.74% |

보수적 방식의 평균 오탐률 감소는 8.30%p이며 평균 탐지율 손실은 9.32%p다. 통합 방식도 오탐은 낮아졌지만 탐지율 손실이 7.25%p다. 정상으로만 판정하면 오탐은 없어지므로 오탐률 하나만으로 개선을 주장하지 않는다.

**이전 spectral 실험의 RF66 오탐 5.45%와 직접 비교하지 않는다.** 이전에는 6개 조건으로 학습하고 1개로 조정했지만, 이번에는 2개 조정 조건을 모두 학습에서 제외해 5개로 학습했다. 이번 대조군은 이 동일한 5조건 학습 모델에서 첫 번째 조정 조건만 사용한 값이다. 임계값 조정 효과는 위 표 안에서 비교해야 한다.

## 고정 프로토콜

입력은 변경 없는 `mcc5-vibration-800hz-spectral66-v1`, 800Hz×512 XYZ, 640ms 비중첩 구간이다. 이번 실험은 구간별 모델 점수를 모두 계산하며 연속 3회 등 시간 필터로 일부 판정을 숨기지 않는다. 음향·RPM 입력을 새로 추가하지 않는다.

기존 `train`의 조건명을 정렬한다. 평가 조건 인덱스 i에 대해 `(i+1)%8` 및 `(i+5)%8`을 조정 조건으로 정하고 나머지 5개로 학습한다. 실제 두 조정 조건은 speed 프로토콜 하나와 torque 프로토콜 하나다. 전 구간이 속한 원시 기록·운전 조건을 유지하며, 학습/조정/평가 간 기록을 공유하지 않는다.

RF는 이전과 같은 300 trees, max depth 12, min leaf 3, sqrt features, seed 42다. 정상/이상 클래스의 전체 가중치 및 클래스 내 기록별 가중치를 균형화한다. 세 정책은 **같은 학습 모델·같은 평가 점수**에 다른 임계값만 적용한다.

- `single_q99`: 첫 번째 조정 조건 정상 점수의 99% 분위수.
- `pooled_q99`: 두 조정 조건 정상 점수를 합친 99% 분위수.
- `max_condition_q99`: 두 조건 각각의 정상 점수 99% 분위수 중 최댓값.

모두 NumPy `quantile(..., 0.99, method="higher")`, strict `score > threshold` 판정이다. 임계값 함수는 정상 조정 점수와 조건 ID만 받으며 평가 점수나 이상 레이블을 입력으로 받지 않는다. 정상 조건 누락, 잘못된 점수 범위, 비유한값은 오류로 처리한다.

실행 전에 다음 **임시 연구용 기준**을 고정해 `protocol.json`에 저장했다. 운영 SLA나 사용자 승인 목표가 아니다.

1. 평균 오탐률 ≤3%.
2. 최악 조건 오탐률 ≤10%.
3. 동일 모델 대조군 대비 평균 탐지율 손실 ≤5%p.

세 기준을 모두 통과한 대안 중 탐지율 우선, 평균 오탐률 차순으로 선택하며 모두 실패하면 `selected: null`이다. 실제로 두 대안 모두 실패했다. 기준을 결과에 맞춰 완화하지 않았다.

## 제한과 해석

- 조정 정상 창은 조건별 140개지만 같은 기록에서 나온 상관된 구간이다. 독립 정상 표본 280개나 다양한 실물 반복 세션으로 해석하지 않는다.
- 평가 조건은 지금까지 반복해서 본 train 조건이다. 새로운 독립 test나 nested CV 검증이 아니며, RF66 후보 선택 역시 이전 실험을 이용했다.
- 기존 validation과 test는 점수 산출·선택에 사용하지 않았다. 캐시 로더의 무결성 검사는 유지했다. 신규 원시 데이터 다운로드나 재추출도 하지 않았다.
- 두 정상 조건만으로 미지의 정상 운전 상태를 대표할 수 있다는 보장은 없다. 통합 q99는 상대적으로 점수가 높은 정상 조건의 꼬리를 희석해 일부 평가 조건의 오탐을 오히려 늘릴 수 있다.
- `torque_20Nm_2000rpm`의 대조군 오탐은 59.29%였고 두 대안에서 0%가 됐지만, 같은 조건의 탐지율은 98.76%에서 통합 60.87% / 보수적 56.86%로 내려갔다. 정상 점수 영역과 이상 점수 영역의 분리 문제가 남은 것이다. 임계값만으로 해결됐다고 해석하지 않는다.
- 운영 경보 억제와 구간별 모델 오탐 감소는 다르다. 향후 연속 판정 정책을 검증한다면 탐지 지연·미탐·데이터 누락과 별도로 평가해야 한다.

다음 우선순위는 실제 부착 상태의 ADXL345 정상 원시 XYZ 또는 동일 규격 특징을 여러 운전 조건·반복 세션에서 수집하고, **조정용 기록과 별도 검증용 기록을 분리**하는 것이다. 공개 데이터 내부에서 본 평가 결과에 임계값을 계속 맞추는 방식은 독립적인 개선 증거가 되지 않는다. 정상 데이터로 오탐을 조정한 뒤에도 별도 이상 데이터에서 탐지율 검증이 필요하다.

## 재현과 산출물

```text
python -m ai.ai1.mcc5_training.calibration --parent <prepared-v1> --prepared <spectral-cache-v1> --output <new-output>
python -m unittest discover -s tests -p "test_mcc5_*.py" -q
```

코드: `ai/ai1/mcc5_training/calibration.py`, 테스트: `tests/test_mcc5_calibration.py`.

출력은 저장소 밖 `../output/mcc5-thu/calibration-v1/`이다. `protocol.json`, `selection.json`, `report.json`, `oof.npz`에 분할·모델 설정·조정 조건별 정상 수·조건별/고장별 지표·모든 평가 점수와 정책별 임계값·데이터/소스 해시를 기록한다. 선택 기준을 통과하지 못했으므로 새 모델 파일을 내보내거나 기존 후보를 덮어쓰지 않았다.

검증: 신규 7개 테스트 및 MCC5 관련 전체 39개 테스트 통과, 제외 0개. validation에 NaN 감시값을 넣는 모의 시험으로 평가에 사용하지 않음을 확인했고, test 행 거부, 조건 분리, 수치 공식, 탐지율 붕괴 후보 거부, 기존 출력 덮어쓰기 방지를 확인했다. 이번 턴에서 백엔드 전체 테스트를 재실행하지는 않았다. 실물·운영 서버·TLS·전원 차단 시험도 미실행이다. 다른 장치 연동 작업 파일은 변경하지 않았다.

## 후속: 정상 오분류 비용 학습

임계값 조정만으로 얻은 탐지율 손실을 개선할 수 있는지 보기 위해 같은 RF66·5조건 학습/2조건 조정/1조건 평가에서 정상 표본의 학습 가중치만 1배·2배·4배로 바꾸는 실험을 추가했다. 클래스/기록 균형 가중치를 만든 뒤 정상 클래스에만 배수를 적용하며 이상 클래스의 가중치는 유지한다. 새로운 정상 데이터를 생성하거나 복제해 독립 데이터가 늘었다고 주장하지 않는다.

임계값은 세 모델 모두 `max_condition_q99`로 고정한다. 정상 가중치 변경은 트리의 학습 경계를 바꾸지만, 정상 점수로 임계값도 조정하므로 단순한 점수 스케일 변화만으로 오탐이 개선될 것이라고 가정하지 않는다.

선택 기준은 평균 오탐 ≤3%, 최악 오탐 ≤10%, **평균 탐지율 ≥77.5545%**다. 탐지율 하한은 최초 동일조건 대조군 82.5545%에서 5%p를 뺀 값이다. 앞선 보수적 임계값 결과 73.24%에서 다시 5%p를 빼며 목표를 계속 낮추지 않는다. 결과를 보기 전에 `normal-cost-v1/protocol.json`에 저장한다. 모두 실패하면 선택 없음으로 남긴다.

1배 모델은 앞선 `calibration-v1/oof.npz`의 모든 점수·보수적 임계값·레이블·run ID와 `atol=1e-14` 내에서 동일해야 하며, 이를 확인한 뒤 2배·4배 후보를 평가한다. 이전 보고서와 현재 데이터 해시·모델 파라미터·조건 분리도 확인한다.

```text
python -m ai.ai1.mcc5_training.cost_sensitive --parent <prepared-v1> --prepared <spectral-cache-v1> --baseline <calibration-v1/report.json> --output <new-output>
```

코드는 `ai/ai1/mcc5_training/cost_sensitive.py`, 테스트는 `tests/test_mcc5_cost_sensitive.py`, 실제 출력은 `../output/mcc5-thu/normal-cost-v1/`이다. 이번에도 validation/test는 점수 산출에 쓰지 않고, 입력 규격·매 구간 분석·운영 서버/장치 설정을 변경하지 않는다.

### 비용 학습 결과 — 개선 없음

| 정상 오류 비용 | 평균 오탐률 | 평균 탐지율 | 최악 조건 오탐률 | 평균 균형 정확도 |
| --- | ---: | ---: | ---: | ---: |
| 1배, 보수적 임계값 대조군 | 3.75% | 73.24% | 15.00% | 84.74% |
| 2배 | 4.20% | 72.25% | 22.86% | 84.03% |
| 4배 | 4.46% | 67.27% | 23.57% | 81.40% |

세 비용의 학습/조정/평가 조건과 q99 조정 정책은 동일하다. 1배 대조군의 전체 OOF 점수·임계값·레이블·run ID를 이전 임계값 실험과 대조해 재현을 확인했다. 2배·4배 비용은 평균 오탐률과 탐지율 모두 악화됐으며 고정한 연구용 기준을 통과한 후보는 없다. `selected: null`, `artifactExported: false`를 기록했다.

정상 오류 비용을 높이면 정상 구간의 절대 점수가 내려가더라도 정상 분포로 다시 맞추는 임계값 역시 내려갈 수 있으며, 트리 경계의 일반화도 변한다. 따라서 비용을 높였다는 이유만으로 미지 운전 조건의 오탐이 낮아졌다고 추정하지 않는다. 이번 결과는 해당 RF·특징·조건 분리·조정 정책에 대한 관찰이며 다른 모든 모델/학습 방법의 가능성을 부정하지 않는다.

후속 비용 테스트 4개를 추가했고, MCC5 관련 전체 **43개 테스트 통과·제외 0개**를 확인했다. 코드 형식 검사도 통과했다. 이 두 실험의 신규 테스트는 합계 11개다. 이번 실험들은 운영 적용을 정당화할 수준의 개선을 얻지 못했으며, 새 모델을 내보내거나 기존 모델/임계값을 교체하지 않았다.
