# MCC5 특징 개선·운전 조건별 안정성 실험

## 범위

이전 비교에서 선택된 Random Forest를 고정하고, 원본 21개 특징에서 파생할 수 있는 수치 변환을 비교한다. 이번 단계는 원시 신호 재전처리·새 주파수 대역 생성·음향 융합이 아니다. 현재 펌웨어의 4개 전송 특징만으로 실행할 수 있다는 의미도 아니다.

- `base21`: 기존 XYZ RMS/peak/첨도/4개 대역 에너지, 21개.
- `ratios36`: 기존 21개 + 축별 4개 대역의 상대 에너지와 crest factor(peak/RMS), 36개.
- `log_ratios36`: 상대 에너지·crest는 동일하게 추가하되 기존 RMS/peak는 `log1p(x/0.01g)`, 대역 에너지는 `log1p(x/0.0001g²)`로 바꾼다. 첨도는 유지한다.

대역 비율 분모는 해당 축의 [0,350)Hz 네 대역 합이다. 양의 진폭·대역 에너지와 유한값을 검사하며 무효 데이터의 0 채우기를 하지 않는다. 변환에는 학습·검증 데이터로 맞추는 통계가 없고 단위 기준값은 고정한다. 파생 특징은 기존 값의 표현을 바꿀 뿐 새 측정 정보를 만들어내지 않는다.

## 데이터 분리 및 선택

1. 검증된 `prepared-v1` 캐시를 사용하고 기존 `train` 8개 운전 조건만 특징 비교에 사용한다.
2. 조건명을 정렬하고 하나를 평가 대상으로 뺀다. 다음 조건(순환)을 임계값 조정 대상으로 빼고 나머지 6개 조건으로 모델을 학습한다.
3. 정상/이상 전체 가중치와 클래스 내 기록별 가중치를 균형화한다. RF 300 trees, depth 12, leaf 3, sqrt, seed 42를 유지한다.
4. 별도 조정 조건의 정상 점수 99% 분위수(higher)를 임계값으로 고정한다. 평가 조건에는 `score > threshold`를 적용한다.
5. 8개 평가 조건이 각각 한 번씩 평가되도록 반복한다. 3개 특징 구성에 같은 분할을 적용한다.
6. 평균 fold 균형 정확도가 높은 구성을 선택하고, 동률일 때 최악 오탐률이 낮은 구성, 그다음 단순한 구성 순으로 선택한다.
7. 95%, 97.5%, 99% 분위수의 민감도 결과도 기록하지만 95%/97.5% 결과로 후보나 최종 임계값을 바꾸지 않는다.
8. 선택을 저장한 뒤 기존 train 전체로 최종 후보를 학습한다. 기존 validation은 임계값 조정과 재사용 진단에만 사용한다. 기존 test는 무결성 검사 이외에 특징 변환·점수 산출·후보 선택에 사용하지 않는다.

실험 계획은 `protocol.json`, 선택은 `selection.json`에 저장한다. 코드·데이터·모델 해시와 fold별 기록/고장 지표, 조정 임계값, 평가 점수는 산출물에 남긴다.

## 해석 제한

- 이 fold 결과로 특징을 선택했으므로 선택된 수치를 독립적인 nested CV 최종 성능으로 주장하지 않는다. RF 모델 종류 역시 이전 실험에서 선택됐다.
- fold마다 조정 정상 데이터가 하나의 기록에서 나온 140개 상관된 창이다. 임계값이 해당 운전 조건에 민감할 수 있다.
- 속도/토크 프로파일 이름은 평가 분리용이지 실시간 RPM·토크 측정 입력이 아니다. 가용하지 않은 현장 RPM을 가정하지 않는다.
- 모델 출력은 교정된 실제 고장 확률이 아니다. 조건별 threshold 수치를 확률로 해석하지 않는다.
- 실제 ADXL345·독립 모터·새 고장 종류 평가가 아니며 펌웨어와 운영 설정은 변경하지 않는다. 현장 정상만으로 오탐을 조정해도 고장 탐지율 검증은 별도로 필요하다.
- `.joblib`은 신뢰하지 않는 파일 로딩 시 코드 실행 위험이 있다. 스크립트에서는 직접 생성한 로컬 파일만 즉시 재로딩해 검증하며 기존 운영 PyTorch 로더에 연결하지 않는다.

## 재현

```text
python -m ai.ai1.mcc5_training.stability --prepared <prepared-v1> --output <new-output>
```

준비 환경은 기존 NumPy/SciPy/PyTorch/scikit-learn 환경이다. 기존 결과 폴더는 덮어쓰지 않는다. 이번 실제 출력 경로는 저장소 밖 `../output/mcc5-thu/stability-v1/`이다.

## 실제 결과 — 채택 보류

검증: 신규 테스트 6개 통과. 전체 테스트 492개 실행, 18개 제외, 실패 0개(474개 통과). test 파티션에 NaN 감시 값을 둔 모의 검사로 평가 경로에서 test를 사용하지 않음을 확인했다. 저장 모델의 validation 전체 출력 재현, golden 원시 구간 수치 계약, 모델·소스 SHA256도 확인했다. 실제 보드·현장 시험은 미실행이다.

각 숫자는 기존 train 안에서 8개 운전 조건을 분리한 fold 평균이다. 앞선 test 탐지율 64.08%와 평가 대상 및 학습량이 다르므로 직접적인 개선율로 비교하지 않는다.

| 특징 구성 | 평균 탐지율 | 평균 오탐률 | 평균 균형 정확도 | 최악 조건 탐지율 | 최악 조건 오탐률 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 기존 21개 | 76.98% | 2.95% | 87.02% | 39.16% | 10.00% |
| 비율·crest 추가 36개 | 78.75% | 4.46% | 87.14% | 33.54% | 14.29% |
| 로그 변환 + 36개 | 78.61% | 5.45% | 86.58% | 35.29% | 16.43% |

고정한 선택 기준에서는 `ratios36`이 선택됐지만, 균형 정확도 상승은 약 0.12%p에 불과하고 오탐 및 최악 조건 탐지율이 악화됐다. **운영 채택 또는 안정성 개선의 근거로 보지 않는다.** 로그 변환도 이번 비교에서 개선을 보여주지 못했다.

`ratios36`의 fold별 threshold는 약 0.5619~0.9810으로 달랐다. 이는 서로 다른 조건과 학습 모델에서 얻은 점수 임계값 범위이며 실제 고장 확률 범위가 아니다. 조정 정상 기록을 한 조건에서만 가져온 영향도 포함하므로 단순히 고정 임계값을 낮춰 해결됐다고 주장하지 않는다.

선택 후 train 전체 재학습 및 기존 validation 재사용 진단은 탐지율 89.13%, 오탐 2/280창이었다. 이 validation은 임계값 조정에도 사용했고 이전 실험에서도 확인했으므로 독립 성능으로 제시하지 않는다. **기존 test의 새 점수는 계산하지 않았다.**

저장 후보: `candidate.joblib`, SHA256 `c87cdf39fd140f357ba8502fe82e7313a6c03263d3c87f7db05bda7dfb7d3aa9`. 수치 계약과 원시 구간 기대 결과는 `golden.json`, 모든 fold 지표는 `stability_report.json`에 있다. 실험 후보 저장과 운영 승인/배포는 별개다.

다음 우선순위는 (1) 여러 정상 운전 기록을 확보하고 조정 기록을 바꿔도 유지되는 임계값인지 확인, (2) 반복 세션·독립 장비로 평가 범위를 확대, (3) 기존 요약값의 재조합을 넘어 원시 파형에서 새 저주파 분포/축 관계가 유용한지 검증이다. 이번 실험만으로 성능 한계가 센서 대역 때문인지 학습 자료·모델 때문인지 단정할 수 없다. 데이터 중복을 늘리거나 이미 본 test에 임계값을 맞추는 방식으로 성능을 개선했다고 보고하지 않는다.
