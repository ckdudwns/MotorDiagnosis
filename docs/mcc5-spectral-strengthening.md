# MCC5 원시 XYZ 기반 모델 강화

## 범위와 상태

800Hz·512샘플의 원시 XYZ를 다시 처리해 기존 21개 특징에 새로운 주파수 분포·스펙트럼 형태·축 간 관계를 추가한다. 이전 `ratios36`처럼 기존 21개 숫자만 재조합하는 실험이 아니다. 실험용 코드와 후보이며, 운영 서버·ESP32 펌웨어·알림 설정은 변경하지 않는다.

사용자 요구: **매 640ms 구간 분석**, window=512, hop=512, 중첩 없음. 한 구간만으로 판정하며 기존 CWRU LSTM의 연속 5구간 조건을 사용하지 않는다. 이 요구를 명세에 반영한 것이지 현재 장치가 무손실 연속 수집을 수행함을 확인한 것은 아니다.

## 특징 추출 계약

기준 코드: `ai/ai1/mcc5_training/features.py:extract`, `ai/ai1/mcc5_training/spectral.py:extract66` 및 `CONTRACT`. 원시 입력은 `float[512,3]`, 열 X/Y/Z, 단위 g이다. 현재 `vibrationRmsRaw`의 단위를 추정해 g로 취급하지 않는다.

- 0~20: 기존 X/Y/Z 각 7개 RMS, 절댓값 peak, Pearson 첨도, 네 대역 파워. 기존 규격과 동일하다.
- 21~34: X의 추가 14개.
- 35~48: Y의 추가 14개.
- 49~62: Z의 추가 14개.
- 63~65: XY, XZ, YZ의 signed Pearson 상관계수.

축별 추가 14개 순서:

1. 상대 파워 8개: [0,25), [25,50), [50,75), [75,100), [100,150), [150,200), [200,275), [275,350) Hz.
2. 정규화 스펙트럼 엔트로피.
3. 스펙트럼 중심 주파수(Hz).
4. 스펙트럼 대역폭(Hz).
5. 최대 파워 주파수(Hz).
6. 최대 bin 파워 비율.
7. 누적 파워 85% 주파수(Hz).

모든 축의 구간 평균을 제거한 뒤 periodic Hann `np.hanning(513)[:-1]`을 적용한다. rFFT에서 **0Hz 초과 350Hz 미만**인 bin만 추가 특징의 분모에 사용한다. 각 bin의 파워를 이 합으로 나눈 비율 p를 사용한다. 이 범위의 단측 계수·정규화 상수는 비율에서 상쇄된다. 기존 21개 절대 파워에는 기존 정규화를 그대로 사용한다.

엔트로피는 `-sum(p*ln(p))/ln(K)`, K는 지지 대역 bin 수이며 0 log 0은 0이다. 중심은 `sum(p*f)`, 대역폭은 `sqrt(sum(p*(f-centroid)^2))`다. 최대값 동률은 낮은 bin을 택하고, 85% 주파수는 누적합이 처음 0.85 이상이 되는 bin이다. 상관계수는 Hann 적용 전 평균 제거 신호로 계산하며 [-1,1]로 수치 오차를 제한한다.

512×3 형태·유한값·±16g 범위·상수 축·유효 대역 에너지를 검사한다. 무효 구간을 0 채워 넣지 않는다. PC 참조 구현의 상수 축/최소 에너지 검사는 실물 누락·포화·수집 품질 검사를 대체하지 않는다.

기존 float32 캐시와 동일한 baseline을 비교하기 위해 모델에 넣는 기본 21개는 float32 변환 후 float64로 승격하며, 추가 45개는 float64다. 이 수치 정책을 golden에 기록한다. ESP32 float32 구현과의 허용오차는 실물/호스트 비교로 정해야 하며 아직 승인하지 않았다. 스펙트럼 후보 66개는 **21개 전송값만으로 복원할 수 없다**.

## 고정 비교 계획

- 이미 다운로드하고 SHA256 검증한 MCC5 2개 ZIP만 사용한다. 원본은 재배포하지 않는다.
- 기존 train/validation 235개 기록만 다시 읽는다. 기존 test 47개 기록의 새 특징을 추출하거나 점수를 계산하지 않는다. 부모 캐시는 기존처럼 전체 무결성 검사를 한다.
- 매 원시 기록의 SHA256을 부모 명세와 대조하고 각 구간의 기존 21개 특징을 부모 캐시와 비교한다. 행의 run ID·window index·split을 유지한다. 불일치 시 중단한다.
- 후보 4개: RF21, RF66, HGB21, HGB66. 모델 설정은 기존 비교와 동일하며 하이퍼파라미터 탐색을 하지 않는다.
- 기존 train의 8개 운전 조건을 정렬해 6개 학습·1개 임계값 조정·1개 평가로 나누고, 모든 조건을 한 번씩 평가한다.
- 정상/이상 클래스 전체 가중치 및 클래스 내 원시 기록별 가중치를 균형화한다.
- 임계값은 조정 조건 정상 점수의 q99, `higher`; 판정은 strict `score > threshold`로 고정한다.
- 평균 fold 균형 정확도, 최악 오탐률, 특징 수, 이름 순으로 선택한다. protocol은 평가 전에, selection은 최종 재학습 전에 저장한다.
- 선택 이후 train 전체 재학습, 기존 validation 임계값 조정/재사용 진단, 직접 생성한 모델 재로딩 및 golden 일치 검사를 한다.

fold 성능은 이번 후보 선택에도 사용하므로 독립 nested CV 성능이 아니다. 예전 test 결과와 직접 비교해 새 test 개선율로 부르지 않는다. 정상 조정 창 140개는 하나의 상관된 기록에서 나온 것으로 독립 표본 140개가 아니다. 운전 조건 분리는 독립 모터/현장 검증이나 새로운 고장 종류 검증이 아니다. 확률형 모델 점수도 교정된 실제 고장 확률이 아니다.

## 매 구간 연동 요구 — 후속 구현

초당 평균 1.5625개 구간을 처리한다. 수집은 이전 구간 계산·HTTPS 전송을 기다리지 않게 버퍼와 작업 경로를 분리해야 한다. No PSRAM 프로파일에서도 메모리·FIFO·샘플링 지속성을 실측 검증해야 한다.

- 7초마다 전송하더라도 그동안 측정한 구간별 특징을 모두 배치에 포함해야 한다. 7초에 한 구간만 측정/전송하면 요구를 충족하지 않는다.
- 각 구간에 장치 ID, boot ID, 단조 증가 구간 순번, 시작 시각, 실제 샘플 수, 규격 버전, 누락·포화 등 품질을 보존한다. 전송 주기와 640ms 수집 구간은 별개다.
- 누락은 판정 불가로 표시하고, 중복은 동일 구간으로 처리하며, 재전송으로 다른 구간이 덮어써지지 않아야 한다.
- 오프라인 배치 재전송은 과거 구간 분석이며 수신 시각을 측정 시각으로 바꾸면 안 된다. 버퍼 부족으로 버린 구간도 집계해야 한다.
- 전 구간 판정과 전 구간 알림은 별개다. 이 후보는 알림에 영향을 주지 않으며, 향후 연속 판정·히스테리시스 등 이벤트 정책은 별도 검증 대상이다.
- 음향은 별도 수집·표시한다. 이번 모델에 소리·MFCC·실측 RPM·전류·토크를 입력하지 않는다.

## 실행과 담당자 전달물

```text
python -m ai.ai1.mcc5_training.spectral prepare --source <verified-zips> --parent <prepared-v1> --output <new-spectral-cache>
python -m ai.ai1.mcc5_training.spectral compare --parent <prepared-v1> --prepared <spectral-cache> --output <new-results>
python -m unittest discover -s tests -p test_mcc5_spectral.py -v
```

새 폴더만 사용한다. 저장소 밖 `../output/mcc5-thu/spectral-cache-v1`, `../output/mcc5-thu/spectral-v1`에 실험 결과를 저장한다.

전달물은 위 두 특징 추출 소스, 모델의 versioned contract, `golden.json`(원시 512 XYZ + 기대 특징 + 기대 점수), `report.json`이다. 선택 전에는 66개를 최종 운영 규격으로 확정하지 않는다. 신뢰되지 않은 joblib 로딩은 코드 실행 위험이 있으며, 연구 후보 파일은 기존 운영 PyTorch 로더에 바로 연결할 수 없다.

## 실제 결과 — 평균 탐지율 개선, 운영 채택 보류

2026-09-07 실행. 기존 train/validation 235개 기록의 32,900개 구간을 추출했다. test 47개 기록은 새 특징 추출·점수 산출에서 제외했다. RF21의 모든 fold 점수·임계값·레이블·run ID가 이전 안정성 실험과 `atol=1e-14` 안에서 재현됐다.

아래는 **기존 train 내부의 8개 운전 조건 분리 fold 평균**이다. 이전 test 탐지율 64.08%와 직접 비교할 수 없으며 독립 성능 검증이 아니다.

RF66에서 `torque_40Nm_1000rpm` 평가 조건의 오탐률이 21.43%였다. 해당 fold는 다른 한 조건의 정상 구간으로 임계값을 조정했다. 공개 데이터의 운전 조건 차이, 한 정상 기록에 의존하는 임계값 조정, 모델/특징 선택의 영향을 분리해 확인해야 한다. 이 결과만으로 원인을 센서 대역이나 특정 알고리즘 하나로 단정하지 않는다.

선택 후 train 전체 학습, 기존 validation 재사용 진단은 탐지율 5,882/6,300=93.37%, 오탐 2/280이었다. validation은 임계값 조정과 과거 실험에도 사용했으므로 **93.37%를 새 test 성능으로 제시하지 않는다.** 최종 연구용 임계값은 `0.79639982470205`이다.

후보 파일 `../output/mcc5-thu/spectral-v1/candidate.joblib`의 SHA256은 `dd7b92515910ec6854d94bf3f1a24387d6ea99746122acaa27c50feb13812007`이다. 원시 예제와 기대 특징/점수는 같은 폴더 `golden.json`, 모든 fold·원본/코드 해시·설정은 `report.json`에 보관한다.

신규 테스트 7개 통과. 전체 499개 실행, 18개 제외, 실패 0개(481개 통과). 단위·스펙트럼 순서·스케일/평균 제거·무효 구간 거부·test 혼입/행 재정렬 거부·모델 저장 재로딩을 검사했다. 실물 ESP32 계산 일치, 연속 수집 누락, 운영 서버 처리량, 현장 오탐 및 실제 고장 시험은 미실행이다.

직접 생성한 SHA256 고정 모델과 소스 해시, golden 점수를 재검증했다. 로컬 PC에서 10회 준비 실행 후 100회 측정한 **원시 특징 추출 + 한 구간 RF 추론**은 중앙값 33.62ms, 95백분위 34.30ms, 최대 44.17ms였다. Python 시작/모델 로딩, 네트워크, 큐, DB 저장, 다중 장치 부하를 포함하지 않는다. 640ms 구간보다 짧았다는 PC 계산 결과일 뿐 ESP32/AWS 실시간성이나 무손실 연속 수집 보증이 아니다. 재현 도구는 산출물 폴더의 `verify_candidate.py`다.

다음 검증 우선순위는 여러 정상 운전 조건/반복 세션으로 조정 데이터의 대표성을 높이고, 모델 학습·임계값 조정에 쓰지 않은 별도 기록에서 오탐과 탐지를 함께 확인하는 것이다. 같은 평가 fold를 보며 임계값만 낮추거나 높인 결과를 독립적인 성능 강화로 주장하지 않는다. 운영 입력 규격은 여전히 채택 보류이며, 21개 기본 경로와 66개 연구 후보를 구분해 전달한다.
