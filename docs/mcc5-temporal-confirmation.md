# MCC5 연속 구간 확인 실험 — 2026-09-08

## 결론

동일한 RF66 예측 점수와 임계값을 유지한 채 **3구간 연속 이상이면 확정**하는 규칙이 이번 연구용 선별 기준을 통과했습니다. 모델 가중치 개선이 아니라 판정 후처리 개선 후보입니다. 서버·펌웨어·알림에는 적용하지 않았습니다.

정상 오탐은 줄지만 이상 탐지율도 낮아집니다. 기존에 반복 확인한 학습 조건의 교차 예측을 재사용했으므로 독립 평가나 실제 ADXL345 성능을 뜻하지 않습니다.

## 비교 조건

- 입력: `spectral-v1/rf66-oof.npz`의 기존 RF66 점수·fold별 임계값. 임계값 재조정·모델 재학습 없음.
- 학습 조건 8개를 각각 평가 대상으로 제외한 기존 교차 예측 사용. 각 모델은 다른 6개 조건으로 학습하고 별도 1개 정상 조건으로 임계값 설정.
- 188개 기록, 총 26,320개 640ms 구간. 원래 validation/test의 예측은 이번 실험에서 수행하지 않음.
- 미래 구간을 보지 않고 현재·과거 구간만 사용. 기록 변경·순번 누락·품질 불량 이후에는 이력을 초기화하고 다시 판정 대기.
- 이력이 부족한 구간은 정상으로 채우지 않고 `-1`(대기/무효)로 별도 기록.
- 공정한 기준 비교: 모든 정책에 이력이 충분한 동일 25,568개 구간을 사용. 정상 구간은 1,088개이며, 각 기록 첫 4개는 이 비교에서 공통 제외됨.
- 전체 26,320개 결과도 별도 공개. 이때 대기 중 이상은 미탐으로 계산하고 대기 중 정상을 정상 판정이라고 주장하지 않음.

실행 전에 고정한 연구용 기준: 조건별 평균 오탐률 ≤3%, 최악 조건 오탐률 ≤10%, 동일 비교 구간의 단일 판정 대비 탐지율 하락 ≤5%p. 이는 운영 SLA나 장비 안전 기준이 아닙니다.

## 시간·품질상의 제한

매 640ms 구간의 원래 모델 점수는 그대로 계산합니다. 3구간 연속 규칙은 총 1.92초 분량의 이력을 확인합니다. 첫 이상 구간 판정 이후 추가로 2구간을 기다릴 수 있지만, 이를 실제 고장 시작부터의 탐지 지연으로 해석하면 안 됩니다. 이 데이터에는 정확한 고장 발생 시점의 정답이 없으며 짧은 이상을 놓치는 위험은 별도 시험이 필요합니다.

실제 적용 시 장치·부팅·모델 버전·운전 조건이 바뀌면 동일한 이력을 이어 쓰면 안 됩니다. 오프라인 도구의 run ID는 이 경계를 대신하며, 실제 서비스용 상태 관리·복원·알림 연결은 이번 작업에 포함하지 않았습니다. RF66의 추가 특징/원시 XYZ 수집 경로도 여전히 필요합니다.

## 재현

저장소 루트에서 NumPy가 있는 기존 분석 환경으로 실행합니다. 출력 폴더는 새 경로여야 합니다.

```bash
python -m ai.ai1.mcc5_training.temporal \
  --parent ../output/mcc5-thu/prepared-v1 \
  --source ../output/mcc5-thu/spectral-v1 \
  --output ../output/mcc5-thu/temporal-v1-recheck \
  --expected-oof-sha256 7ed70783c1f05c6bc7c07ea128fb6c562ff762dde2d3e63c1ed04c87e6611a27
```

`protocol.json`에는 정책·선별 기준·입력/코드 해시를 기록하고, `report.json`에는 공통·전체 구간 지표를 모두 보존합니다. `predictions.npz`는 run/순번/정답/정책별 대기 포함 판정이며, `selection.json`은 후보명과 판정 파일 해시입니다. 입력 순서·정답·fold 분리·임계값이 원래 기록과 다르면 중단합니다. 모델 파일은 새로 만들거나 교체하지 않습니다.

회귀 테스트에는 미래 값 미사용, 순간 이상 억제, 누락·기록 변경·품질 불량 시 초기화, 대기 미탐 집계, 입력 해시·fold 누출 차단을 포함합니다.
