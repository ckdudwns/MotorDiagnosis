# 실제 RPM 연동 준비 — 공통 수신·저장·표시

## 구현 범위와 아직 필요한 정보

이 단계는 **장비와 무관한 연동 기반**이다. 실제 장비에서 RPM을 읽는 기능은 아직 구현하지 않았다. 장비 모델·통신 방식·속도 항목을 모르는 상태에서 주소, 핀, 단위 배율이나 만료 시간을 임의로 정하지 않는다. ESP32 펌웨어도 변경하지 않았으며 현재처럼 `rpm: null`을 전송한다.

목표 값은 진단 대상 **모터 축의 실제 회전수(rev/min)**다. 추후 장비 매뉴얼에서 실제 속도 피드백인지 확인해야 하며, 목표 속도·정격 회전수(`ratedRpm`)·주파수 환산값·추정 속도를 실측으로 취급하지 않는다. 감속기 출력축 속도와 모터 축 속도도 구분해야 한다. 원격 설정이나 다른 선택 개발 항목은 이 변경에 포함하지 않는다.

장비 연결을 구현하기 전에 다음을 확인한다.

- 장비 제조사·모델·통신 매뉴얼, 실제 속도 피드백 제공 여부와 대상 축
- 연결 방식과 읽기 항목 주소, 데이터형·바이트 순서·단위·배율·방향 표시 방식
- 품질/통신 오류 표시, 갱신 주기, 장비 시각 또는 수신 시각의 의미, stale 판정 기준
- 기존 제어와 충돌하지 않는 읽기 전용 접근 권한과 실제 보드 연결 조건

하드웨어가 확인되면 읽기 어댑터 → 측정 시점 고정 → ESP32 영속 버퍼/재전송 → 백엔드 경로를 연결한다. 재전송할 때 원래 RPM·측정 시각·출처·상태를 보존하고, 실패한 값을 마지막 정상값이나 정격값으로 대체하지 않는다. 현 단계 테스트 값은 자동 검증용 fixture이며 실물 취득 증거가 아니다.

## 선택적 텔레메트리 확장

기존 `/api/telemetry/ingest`와 `/api/telemetry/bulk`를 사용한다. 기존 인증·장치 매핑·sequence 중복 검사에 그대로 종속되며 별도 무인증 수신 경로는 없다. MQTT도 기존 브리지의 HTTP 수신 경로를 재사용한다. 새 필드를 보내려면 백엔드를 먼저 배포해야 한다. 구버전 백엔드는 알 수 없는 필드를 거부한다.

기존 필드는 그대로 유지한다. 새 필드 중 하나라도 보내면 `rpm`, `rpmStatus`, `rpmMeasuredAt`, `rpmSource` 네 필드를 모두 명시해야 한다.

| 필드 | 의미와 규칙 |
| --- | --- |
| `rpm` | 유효한 실제 속도 피드백은 0 이상의 유한 JSON 숫자. `0`은 정상적으로 측정된 정지다. 숫자 문자열은 허용하지 않는다. 그 외 상태는 반드시 `null`. |
| `rpmStatus` | `valid`, `unavailable`, `stale`, `invalid` 중 하나. |
| `rpmMeasuredAt` | 측정 시각 또는 `null`. 시간대가 명확한 RFC3339 달력 형식, 소수초 최대 6자리. 저장은 UTC `Z`와 밀리초로 정규화한다. 텔레메트리 `timestamp`보다 미래이면 거부한다. |
| `rpmSource` | 발신 측에 설정된 속도 피드백 출처 식별자 또는 `null`. 비어 있지 않은 최대 160자 문자열이며 제어문자를 허용하지 않는다. 서버가 장비를 인증하거나 실측 여부를 검증했다는 증명은 아니다. |

| 상태 | `rpm` | 측정 시각·출처 |
| --- | --- | --- |
| `valid` | 숫자, 0 포함 | 둘 다 필수. 합성 텔레메트리(`isSynthetic: true`)에는 사용할 수 없다. |
| `unavailable` | `null` | 시각은 `null`. 출처는 설정되어 있으면 식별자, 아직 없으면 `null`. |
| `stale` | `null` | 마지막 관측의 시각·출처를 모두 보존. 오래된 숫자는 전송하지 않는다. |
| `invalid` | `null` | 출처와 시각은 알려진 경우 보존. 시각이 있으면 출처도 필수. 유효한 시각이 없으면 `null`. |

`valid`는 **해당 기록의 취득 당시 발신 측이 보고한 유효 상태**이지 현재 시각의 신선도 보장이 아니다. 장비별 만료 기준은 아직 정하지 않았고 서버가 임의의 TTL로 상태를 바꾸지 않는다. 장시간 통신 단절 후 재전송해도 측정 시각을 서버 수신 시각으로 교체하지 않는다. 소수초 정밀도에 맞게 텔레메트리 시각을 측정 시각과 같거나 이후로 설정해야 한다. 이 확장은 마이크로초 정밀 저장, signed 방향 속도, 추가 속도 환산을 제공하지 않는다.

아래는 기존 텔레메트리에 합칠 **필드 조각**이며 완전한 POST 본문이나 실제 장비 값이 아니다.

```json
{
  "rpm": 1450.25,
  "rpmStatus": "valid",
  "rpmMeasuredAt": "2026-09-06T00:00:00.000Z",
  "rpmSource": "equipment-feedback:shaft-speed"
}
```

미연결 상태를 명시하는 발신 측은 다음 조각을 사용한다.

```json
{
  "rpm": null,
  "rpmStatus": "unavailable",
  "rpmMeasuredAt": null,
  "rpmSource": null
}
```

## 저장·조회·화면·내보내기

- 새 메타데이터는 원시 텔레메트리와 함께 저장되고 재시작 후에도 복원된다. 같은 장치·sequence에서 RPM 정보가 달라지면 기존 중복 충돌 규칙에 따라 거부된다.
- 기존 메시지가 새 필드를 보내지 않으면 과거 정규화 결과·중복 해시를 유지한다. 레거시 숫자에 `valid`나 측정 출처를 자동 부여하지 않는다.
- 차트는 명시적으로 `valid`인 숫자만 표시하고 다른 상태는 결측으로 표시한다. 레거시 숫자는 기존처럼 표시하되 툴팁에 **상태정보 없음**으로 구분한다. 툴팁은 측정 시각·출처·상태를 텍스트로 표시한다. `ratedRpm`으로 채우지 않는다.
- 텔레메트리 JSON 조회에는 원래 필드 이름으로 상태·시각·출처가 유지된다. CSV/XLSX 데이터셋 행에는 새 기록에 한해 `rpm_status`, `rpm_measured_at`, `rpm_source`가 추가된다. 레거시/새 기록이 섞인 표의 레거시 행에는 해당 셀이 빈 값이다. 첫 행이 레거시여도 이후 행의 확장 필드가 누락되지 않는다.
- 이미 동결된 데이터셋의 행·manifest·checksum은 변하지 않는다. RPM 유효 상태로 학습 라벨을 검증 처리하지 않으며 기존 taxonomy/provenance 정책을 유지한다.

## 자동 검증과 미실행 범위

`tests/test_measured_rpm.py`는 0/결측/음수/비유한값/타입/시각/출처 조합, 단건·bulk HTTP, 인증, 조회, 재시작, 중복 처리, 혼합 형식 내보내기와 동결 snapshot 보존을 검사한다. 대시보드 실행 테스트는 상태별 차트 결측, 레거시 구분, 툴팁 시각·출처와 텍스트 안전성을 검사한다.

실제 장비·보드 RPM 취득, 장비 측 단선/타임아웃, MQTT 브로커 종단 간 전송, 현장 속도 정확도와 장시간 시험은 **미실행**이다. 장비 정보가 확인된 후 연결 구현과 함께 검증해야 한다.
