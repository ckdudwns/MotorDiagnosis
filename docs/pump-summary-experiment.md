# 담수급수 모터 요약 특징 학습 실험

최신 main `e21f497` 기반의 오프라인 학습·평가 경로다. 담수급수 모터 한 대의
두 센서 시트를 읽으며, RAS의 데이터 없음 행과 definitions 선택지를 측정치로
취급하지 않는다. 현재 공개된 수집 코드에는 이 엑셀 컬럼 계약이 없으므로
기존 ADXL345 800 Hz, g, mm/s 또는 dB 계약을 적용하지 않는다.

## 실행

저장소 루트에서 Python 3.12.x와 루트 `.venv`를 사용한다. 직접 의존성은
기존 requirements.txt의 NumPy뿐이며, 엑셀은 표준 라이브러리로 읽는다.
원본은 저장소 밖에 보존한다. 출력 디렉터리는 매번 새로운 경로를 지정한다.

```bash
python -m ai.ai2.pump_pipeline "../new data/multi_20260907_1433_20260910_1433.xlsx" --output output/pump/audit
```

미확정 단위의 수치를 사용하는 탐색 실험은 명시적으로 특징을 선택해야 한다.
다음은 특징 형태를 비교하는 실험이며 물리적 정상 범위의 승인이 아니다.

```bash
python -m ai.ai2.pump_pipeline "../new data/multi_20260907_1433_20260910_1433.xlsx" --output output/pump/experiment --exploratory-features cf_a_1 cf_a_2 cf_a_3 sk_a_1 sk_a_2 sk_a_3 ku_a_1 ku_a_2 ku_a_3
python -m unittest tests.test_pump_pipeline -v
python -m black --check ai/ai2/pump_pipeline.py tests/test_pump_pipeline.py
```

학습을 끝낸 뒤 새 파일을 **재학습하지 않고** 시간순으로 검증하려면 저장한
`model.json`을 명시적으로 넘긴다. 이 명령은 모델 계수·임계값을 변경하지 않는다.

```bash
python -m ai.ai2.pump_pipeline "../new data/new_export.xlsx" --output output/pump/replay --model output/pump/experiment/model.json
```

## 처리 계약

- 원본 SHA-256과 시트별 건수·누락 라벨·지연·동일 시각/ID·상수 특징을 보고한다.
- 문서 ID, 시각, 라벨, 카운터는 학습 특징으로 허용하지 않는다. 빈 라벨은 미확인이다.
- 수식 셀은 실행하거나 캐시 결과를 신뢰하지 않고 거부한다.
- createdAt의 시간대를 UTC로 정규화한다. 단, 장치 시계 신뢰성은 아직 미검증이다.
- 두 센서의 공통 관측 기간에서 60%/80%의 동일 절대 시각 경계를 사용한다.
  공통 기간 이후 데이터도 전진 시험에 포함하므로 센서별 시험 길이는 다를 수 있다.
- 각 분할 안에서 **정확히 5초 간격**인 과거 12행의 마지막 값·평균·표준편차·처음
  대비 변화량을 만든다. 한 행이라도 누락되면 창을 초기화한다. 12행의 처음부터
  마지막까지는 55초이므로 발표에서는 최근 약 1분 이력이라고 설명한다.
- 스케일과 PCA는 학습 분할에서만 계산한다. MAD가 0인 특징은 제거하고 목록을 남긴다.
- robust 편차와 PCA 잔차를 비교하며 각 99백분위 기준은 별도 조정 분할에서 계산한다.
  99백분위는 초기 실험 설정이며 검증된 정상 오탐률이나 운영 한계가 아니다.
- 기준선용 학습 자료도 정상이라고 확인되지 않았다. 고장이 포함됐을 가능성이 있다.
- 예측은 정확히 5초 간격의 다음 특징을 대상으로 Ridge 후보를 조정 분할에서 선택한다.
  시험 오차를 직전 값 유지 예측과 비교한다. 고장 시점·잔여수명 예측을 뜻하지 않는다.
- 검증 기간이 부족한 센서는 모델을 발행하지 않는다. 센서들을 별도 모터로 간주하지 않는다.

## 현재 예측 입력과 학습/시험 분리

학습 명령(`--exploratory-features`)과 고정 모델 재생 명령(`--model`)은 분리되어 있다.
새 엑셀을 `--model`로 재생해도 저장된 `model.json`을 다시 학습하거나 덮어쓰지 않는다.
`FixedPumpAnalyzer`는 실제 수신 어댑터가 호출할 운영용 순차 분석기다. 센서별로 이전
기록을 보관하므로 처음 12건 이후에는 새 측정값 **한 건**마다 다음 5초의 9개 특징을
예측한다. 매번 12건을 다시 전송할 필요는 없다.

입력은 같은 센서의 `createdAt`이 정확히 5초 차이이고, `sequence`가 정확히 1씩 증가하는
최근 **12개 행**이다. 누락·재부팅에 따른 순번 불연속·품질 불량은 해당 센서 이력을 즉시
끊고 다시 12건을 쌓는다. 실시간 수신 오차의 허용 범위는 현장 시계 자료를 받은 뒤 별도
계약으로 정한다. 현재는 평가와 같은 엄격한 5초 계약을 사용한다.

현재 제공된 엑셀의 `cnt`는 실제 telemetry sequence가 아니며 5초 행에서 반복된다. 따라서
`--model` 엑셀 재생은 정렬된 행 순서로 만든 `replay_row_order`만 사용한다. 이 값은 운영
식별자가 아니다. 실제 수신 어댑터는 장치가 부여한 `sequence`와 측정 시각을 전달해야 한다.

한 입력은 9개 선택 특징의 마지막 값, 12행 평균, 표준편차, 첫 행 대비 변화량으로 만든
36개 수치다. 새 실제값이 들어오면 직전 예측의 raw/표준화 MAE를 함께 반환한다. 이는
다음 특징값 예측 오차이며 고장 발생 시각·고장 확률·RUL 예측값이 아니다.

분할은 행을 무작위로 섞지 않는다. 두 센서가 함께 관측된 기간의 시작·종료 시각을 잡고,
그 기간의 앞 60%는 학습, 다음 20%는 임계값과 Ridge 계수 선택, 마지막 20%부터는 시험으로
사용한다. 센서 3처럼 이후 관측이 더 있으면 그 이후 행도 전진 시험에 포함한다. 따라서 학습에는
조정·시험 행이 들어가지 않으며, 12행 창도 분할 경계를 넘겨 만들지 않는다.

운영 연결 때는 학습 시 만든 `model.json`을 읽는 별도 추론 함수가 최근 12개 행을 받아야 한다.
그 함수의 결과는 실제값이 들어오기 전의 다음 5초 특징 예상치이며, 고장 발생 시각·고장 확률·RUL
예측값으로 표시하지 않는다.

## 출력

| 파일 | 의미 |
|---|---|
| audit.json | 원본 체크섬과 시트 전체 품질 검사 |
| model.json | 특징 순서·변환·센서별 기준선/PCA/5초 예측 가중치 |
| evaluation.json | 분할·표본 수·시험 기준 초과 비율·예측 오차 |
| predictions.json | 시험 구간의 센서별 편차와 실험용 점수 |
| event-replay.json | 기존 AI2 lifecycle로 재생한 센서별 관측 이벤트 |
| replay.json | 고정 모델에 새 파일을 한 행씩 넣은 분석·직전 예측 오차 |
| replay-summary.json | 재생 범위·비교 수·평균 오차·건너뛴 행 |

점수는 `min(100, 75 * robustDeviation / calibrationThreshold)`를 반올림한다.
고장 확률이 아니다. 기준 초과 비율을 정확도나 오탐률로 보고하지 않는다.
이벤트는 실험 식별자로 30초 지속 진입/회복 조건을 사용하며 원본 모터 이벤트를
갱신하지 않는다. 공백은 관측 중단으로 처리한다. UUID는 재실행 시 달라질 수 있다.
현재 모델은 기존 운영 checkpoint 형식과 다르며 운영 서버가 자동 로딩하지 않는다.

## 운영 연결 전 남은 일

1. 센서별 필드 단위·계산 구간·중력 처리·부착점 및 실제 장치 매핑 확인.
2. 실제 API/MQTT/Elasticsearch 중 접근 가능한 수집 계약과 인증 경로 확인.
3. 수신 어댑터에서 `FixedPumpAnalyzer`를 호출하고, 결과·예측 오차를 대시보드에 표시.
4. 운영 검토 라벨로 경고 임계값·고장 전 경고 시간을 검증하고 운영 전환 승인.

이 PR은 학습 실험, 고정 모델 순차 재생과 기존 lifecycle의 로컬 재생까지다. 실제 알림 발송,
Elasticsearch 업데이트, 자동 재학습, 현장 고장 예측·운영 배포는 포함하지 않는다.
단위가 검증되기 전 실험 결과를 운영 모델로 연결하지 않는다.
