# 기획서 추가 항목 1·3·4·5 — 신호 분석 운영 확장

기준: `main 4d1838f`, 브랜치 `feat/signal-analysis-operations`.
최종 요청에 따라 **2번 실제 RPM 취득 및 추가했던 진동 기반 추정 RPM은 이번 작업에서 제외한다.**
기존 실측 RPM 수신·저장·표시 기반은 보존하며 펌웨어는 `rpm:null`을 유지한다.
1번의 RPM 기준선 지원은 외부에서 유효한 실측값이 들어오는 경우의 판정 기능이며 새 취득 어댑터를 뜻하지 않는다.
이 문서는 기존 API v1.3 위의 확장 계약이다. 원본 기획서·명세서 파일은 변경하지 않았다.

## 1. 설비별 통계 기준선의 실시간 적용

기존 `PUT /api/anomaly/rules/{assetId}`에 선택적 `signalBaselines`를 추가한다.
기존 `anomaly-rule:write`·사이트 권한에 더해 기준선 읽기 권한과 기준선의 모든 학습 사이트 접근 권한을 확인한다.
기준선 등록 API로 이미 등록된 **동일 사이트·설비**의 기준선만 선택할 수 있다.

```json
{
  "reason": "정상 구간 통계 검토 후 이 설비의 음향 기준 적용",
  "signalBaselines": {
    "acousticRmsRaw": {
      "baselineVersion": "실제로 등록한 기준선 버전",
      "feature": "해당 기준선의 음향 RMS 특징 키",
      "unitNote": "INMP441 raw PCM RMS, uncalibrated",
      "scale": 1000
    }
  }
}
```

위 버전·특징 키·scale은 형식 설명용이며 실제 적용값이 아니다. 선택은 현재 API로 수행한다.
새 통계 모델을 자동 승인·배포하는 기능이나 기준선 선택 전용 화면을 추가한 것은 아니다.

- 입력은 `vibrationRmsRaw`, `acousticRmsRaw`, `rpm` 중 1~3개. 선택별 키는 예시의 네 개로 고정한다.
- 등록된 특징의 `normal_range=[lo,hi]`를 복사한다. `scale`은 양의 유한한 동일 단위 폭이다. 표준편차 0에 임의 기본값을 넣지 않는다.
- 값이 정상 범위 안이면 0, 밖이면 `min(100, round(100 × 범위 밖 거리 / scale))`. 구현은 상한 적용 후 정수 반올림한다.
- 결합은 **사용 가능한 신호 점수의 최댓값**(`max_available_v1`). 모두 미측정이면 점수는 `null`; 0이나 정상으로 보정하지 않는다.
- RMS는 요청의 `unitNote`와 수집된 단위 문자열이 정확히 같아야 한다. RPM은 `rpmStatus=valid`인 경우만 사용하며 유효한 정지 0과 결측을 구분한다.
- 서로 다른 특징·센서·단위를 자동 변환하지 않는다. 등록 특징이 실제 같은 RMS/측정 방법으로 생성됐는지 승인자가 확인해야 한다. 공개 데이터의 FFT/MFCC·정규화 RMS를 원시 PCM RMS에 그대로 연결하지 않는다.
- 최초 선택 전에는 기존 점수 경로를 유지한다. 선택 후 요청에서 `signalBaselines`를 생략하면 기존 선택을 유지한다. 빈 객체·null은 유효한 선택이 아니다. 전체 규칙 중지는 기존 `active:false`를 사용한다.
- 정상 범위·scale·단위·기준선 버전·규칙 버전을 규칙 이력과 각 수집 행의 `anomalyEvidence`에 고정한다. 이후 기준선 변경이나 조회가 과거 점수를 다시 계산하지 않는다.
- 점수의 표시 상태는 기존 50/75 구간을 따르며, 실제 이벤트 진입·해제는 설비 규칙의 임계값·실제 경과 지속시간·히스테리시스로 결정한다. 센서 고장 억제 경로도 유지한다.

## 3. 요약과 분리된 특징·원시 파형

### 장치 측정 프로파일 `edge-statistics-v1`

현재 공통 취득 창의 **0.64초**를 사용한다. 아래 24개 통계 특징만 계산하며 RPM을 추정하거나 생성하지 않는다.

| 채널 | 표본률 / 표본 수 | 원시 단위 | 대역 경계(Hz) |
| --- | --- | --- | --- |
| vibrationX/Y/Z | 800 / 축별 512 | ADXL345 변환 가속도 `g`, float32 | [0,50), [50,100), [100,400] |
| acoustic | 16000 / 10240 | I2S 우측 이동 후 signed PCM24 `pcm24`, float32 | [0,1000), [1000,2000), [2000,8000] |

값은 교정된 음압·진동 속도가 아니다. 가속도의 중력/DC도 원시 창에 보존한다.
각 채널은 DC 포함 RMS, 절댓값 peak, 중심 4차 모멘트/분산²인 **Pearson 첨도**를 계산한다.
상수 창의 첨도는 `null`이다. excess kurtosis가 아니다.
대역 에너지는 각 FFT 블록 평균 제거, 사각 창, 단측 스펙트럼 제곱/N², DC 제외·Nyquist 1배·나머지 2배다.
진동은 512점 한 블록, 음향은 2048점 다섯 블록의 에너지 평균이다. 단위는 각 입력 단위의 제곱이며 대역 적분 PSD/Hz가 아니다.
기존 요약 RMS/peakHz의 평균 제거·Hamming 처리와 구분한다. 이 새 특징으로 기존 요약 필드를 덮어쓰지 않는다.

### 보존·전송 정책

- `secrets.h`의 `EDGE_ANALYSIS_ENABLED_VALUE=true`로 명시적으로 활성화한다. 예제 기본값은 false.
- 정상 특징 프레임은 마지막 저장 후 최소 30초에 한 번, **다음 유효 측정 창**에서 저장한다. 측정 설정·HTTP 처리 시간만큼 늦어질 수 있다.
- 원시 데이터는 관리자가 사유를 적어 요청한 **다음 유효 창 한 개**만 보존한다. 자동 이상 전후 녹음·상시 중앙 녹음은 이번 정책에 포함하지 않는다.
- PSRAM이 감지되고 UTC가 확정된 경우에만 분석 창을 만든다. 미확정 시각을 꾸며내지 않는다. 기존 요약 오프라인 수집은 그대로 유지한다.
- 요약 패킷과 같은 sequence·timestamp·장치/사이트/설비를 사용한다. timestamp는 기존 패킷의 창 완료 시각(초 정밀도)이며 시작 시각 또는 하드웨어 절대 동기화 정밀도를 보장하지 않는다.
- 별도 LittleFS 파일 8개, 프레임당 최대 96KiB. 기존 48바이트 텔레메트리 링/NVS sequence를 변경하지 않는다.
- 임시 파일→flush/rename→길이·CRC 읽기 검증. 오래된 sequence부터 한 번에 한 파일 전송, 서버의 200/201·accepted·동일 sequence·frameId 확인 뒤에만 삭제한다. 재시작에도 파일을 재전송한다.
- 슬롯이 가득 차면 미확인 파일을 덮어쓰지 않고 새 분석 창을 생략한다. 분석은 24시간 무손실 버퍼가 아니다. 파형 요청은 나중에 만료될 수 있다.
- 손상 파일은 지우지 않고 분석 채널을 중지한다. 서버가 만료/매핑 불일치로 영구 거부하는 미확인 파일도 자동 폐기하지 않는다. 운영자는 원본을 보존해 원인·서버 수신을 확인한 뒤 로컬 복구해야 한다. 자동 원격 삭제 명령은 없다.
- 전송/폴링은 최소 5초 간격의 메인 루프에서 수행하며, 저장된 파일이 모두 확인된 뒤 새 요청을 조회한다. 기존 HTTPS CA·장치 ingest 인증을 재사용하고 리디렉션은 금지한다.
- 요약 INGEST_URL의 `/api/telemetry/ingest`를 같은 origin의 `/api/devices/{deviceId}/analysis`로 바꾼다. 별도 외부 목적지를 허용하지 않는다.

### API·권한·저장소

| 메서드·경로 | 인증 / 동작 |
| --- | --- |
| POST `/api/devices/{D}/analysis/requests` | 로그인 사용자 `device:write` + `telemetry:read` + 사이트 접근. 활성·인증 등록 장치의 현재 매핑을 재검증. |
| GET `/api/devices/{D}/analysis/pending` | 해당 장치 ingest 토큰. 현재 매핑과 미완료·미만료 요청 ID 또는 null. |
| POST `/api/devices/{D}/analysis` | 해당 장치 ingest 토큰. 별도 특징/요청 원시 프레임 영속화. 201 신규, 200 동일 재전송, 409 다른 내용. |
| GET `/api/devices/{D}/analysis?cursor=...` | 로그인 사용자 `device:read` + `telemetry:read` + 사이트 접근. 현재 설비 기록을 최신순 100개씩, `nextCursor`로 끝까지 조회. |
| GET `/api/analysis/{frameId}` | 로그인 사용자 `telemetry:read` + 원래 사이트 접근. 전체 원시 포함 불변 JSON 및 SHA256, 미라벨 상태. 장치 ingest 토큰으로 다운로드 불가. |

요청 본문: `{"siteId":"SITE-01","assetId":"SITE-01-GEN-01","reason":"소음 확인","requestId":"32자리 소문자 hex"}`.
requestId 생략 시 서버 발급. 같은 사용자·대상·사유·ID 재시도는 같은 요청을 반환한다. 다른 내용 재사용은 409.
장치별 미완료 요청 한 개, 유효기간 5분. 유효기간 내 취득했다면 네트워크 복구 후 업로드 가능하다(프레임 보관기간 이내).
장치용 pending 응답은 `requestId`와 `expiresAtEpoch`(UTC Unix 초, 소수 초 포함)를 함께 반환하며 대기 요청이 없으면 둘 다 null이다.
펌웨어는 새 파형 생성 전에 취득 시각과 현재 UTC를 만료 시각과 대조한다. 만료 경계 이상·만료 정보 누락/오류·알 수 없는 시각이면 요청을 비우고 기존 30초 주기의 특징 수집을 계속한다.
만료 검사는 새 취득에만 적용한다. 유효할 때 저장한 outbox 파일의 재전송/ACK 처리는 변경하지 않는다.
서버를 먼저 갱신한 뒤 펌웨어를 배포한다. 새 펌웨어는 만료 정보가 없는 구버전 서버 응답으로 원시 파형을 생성하지 않는다.
수집 시각은 요청 생성 초 정밀도 오차 1초를 허용한다. 클라이언트 자체 보고 시각이며 위변조 방지 서명이 아니다.

프레임의 정확한 루트 필드는 `schemaVersion:1, featureVersion:"edge-statistics-v1", deviceId, siteId, assetId, sequence, timestamp, requestId, channels`.
실험용 분석 v2는 이번 배포 계약에 포함하지 않는다. 미배포 개발본을 제거한 것으로 운영 DB·장치의 저장 데이터를 삭제하거나 변환하지 않는다.
네 채널 각각 `sampleRateHz, sampleCount, unit, features`를 보낸다.
features의 정확한 키는 `rms, peak, kurtosis, bandEnergy`(3개 배열).
원시 창에서는 네 채널 **모두** `samplesFloat32LE`(float32 little-endian의 base64)를 추가하고 해당 requestId를 보낸다.
특징만 보낼 때 requestId는 null이며 원시 배열을 넣지 않는다. 부분 파형·NaN/Infinity·비정상 길이/단위는 거부한다.
새 POST 프레임에만 1MiB 요청 상한을 적용하며 기존 API의 64KiB 상한은 유지한다.

`ANALYSIS_DB_PATH`(기본 `output/analysis.sqlite3`)는 일반 상태 체크포인트와 별도다.
프레임은 취득 시각부터 7일, 장치당 25,000개, 전역 JSON 본문 합계 256MiB 상한이다.
SQLite 인덱스·WAL·파일 오버헤드까지 256MiB라는 뜻은 아니다. 디스크 여유와 백업을 별도로 관리해야 한다.
상한 도달 시 기존 프레임을 축출하지 않고 503으로 거부한다. 시작·조회·정기 작업에서 만료를 정리하므로 새 쓰기가 없어도 만료된다.
파형 내용은 요약·runtime 체크포인트에 복제하지 않는다. 요청/프레임 ID를 가진 장치는 만료 후에도 삭제·ID 재사용을 금지하는 작은 이력 표식을 유지한다.
장치 재매핑 전 기록을 새 설비 목록에 섞지 않는다. 과거 이벤트는 자신의 원래 사이트·설비 범위로 참조한다.

### 화면·이벤트·AI1 연결

장치 운영의 **분석 기록 조회**에서 특징·요청 상태·페이지를 확인한다.
사유를 입력하고 원시 음향 보존을 확인한 뒤 파형을 요청한다. 저장 성공과 후속 조회 실패는 별도로 표시하며 응답 유실 재시도는 같은 ID를 사용한다.
파형을 받은 행만 보기/다운로드 버튼을 제공한다. canvas는 전체 표본의 min/max 구간으로 그리며 다운로드 JSON은 축소되지 않은 전체 float32 표본을 담는다.
미리보기와 대상 확인에는 파싱한 JSON을 사용하되, 다운로드는 원본 HTTP JSON 텍스트를 재직렬화하지 않고 저장한다. 숫자 표기(예: `4999947392.0`)를 유지하여 AI1 체크섬과 일치시킨다.
이벤트 상세에도 기존 전후 요약 시계열과 별도로 동일 범위의 분석 참조를 표시한다. 요약 `rawDataMissing`은 원시 파형 보존 여부가 아니다.
장치 운영의 요청 이력은 현재 설비·장치 범위의 최근 20개를 표시한다. 이벤트 상세는 같은 사이트·설비·장치 조건에 더해 이벤트 문맥의 from~to(양 끝 포함)에 **생성된 요청**만 표시하며, 이후 요청의 완료 여부로 과거 사건과 연결하지 않는다. 파형 기록은 만료까지 cursor로 모두 조회할 수 있다.

다운로드한 파일을 저장소 루트에서 다음과 같이 변환한다:

```text
python -m ai.ai1.edge_handoff analysis-<frameId>.json ai1-edge-input.json
```

변환기는 SHA256와 프레임 프로파일을 검증하고 원시 표본에서 24개 특징을 재계산한다.
`ai1-edge-handoff-v1` 산출물은 전체 신호·표본률·단위·featurePipelineVersion·sourceRef·sourceSha256·artifactSha256를 가진다.
기존 출력 파일은 덮어쓰지 않는다. C++→실제 로컬 HTTP→화면 다운로드 핸들러(테스트 DOM/Blob)→AI1 체크섬·특징 수치 일치 테스트를 제공한다. 실제 브라우저/보드 종단 간 시험은 별도다.
라벨은 `unlabeled`, `target_label:null`, `training_eligible:false`다. 자동 정답 승격·모델 학습·운영 배포를 수행하지 않는다.
학습 담당자가 단위 호환·결측 첨도 처리·검수 라벨·split/데이터셋 동결을 확정한 뒤 이 버전의 특징을 별도 학습 입력으로 사용한다. 기존 CWRU/MIMII 특징 공간과 자동 혼합하지 않는다.

## 4. 이벤트 발생 당시 설치 정보

신규 이벤트의 `installationSnapshot`에 위치·방향·고정 방식·음향 방향·주변 소음·사진 참조·설치점 ID와 버전 시각을 깊은 복사한다.
재전송 이벤트는 기록된 생성/변경 시각과 before 이력을 이용해 당시 상태를 복원한다. 현재 설치 변경이 기존 이벤트를 덮어쓰지 않는다.
기존 이벤트에 발생 당시 증거가 없거나 설치점 생성 이전이면 `unavailable`; 현재 정보를 과거 사실로 채우지 않는다.
시각은 기존 설치 변경 기록 정밀도를 따른다. 같은 타임스탬프의 사건은 시간만으로 선후를 더 세밀하게 판별할 수 없다.
사진은 당시 **URI 참조 문자열**이지 이미지 바이트의 영구 보존본이 아니다. 화면에서 외부 사진을 자동 요청하지 않는다.

## 5. 정기 건강 보고 간격

`healthReportIntervalMs`: 정수 10,000~300,000ms, 기본 30,000ms.
새 명령 v2, NVS 저장 v2, 재부팅 복원·적용 결과·운영 화면을 함께 연결한다.
장애 상태 변화와 미확인 health 보고는 기존 최소 5초 간격, 실패는 기존 최대 60초 backoff를 유지한다.
메인 루프·센서 취득·네트워크 처리 때문에 정확한 주기 SLA를 보장하지 않는다.
기존 두 필드 명령/저장소의 호환 방식과 배포 순서는 [원격 설정 문서](limited-remote-config.md)를 따른다.

## 배포 전 확인 및 검증 한계

백엔드 영속 경로·디스크 보관 예산·사이트 접근·장치별 인증/TLS를 설정한다.
새 펌웨어와 PSRAM 구성을 확인한 뒤 분석 기능을 켜고, 새 건강 주기 명령을 발행한다. 서버 요청 저장만으로 장치 적용/파형 수신을 완료 처리하지 않는다.
현재 PC 수치/HTTP/화면 회귀 검사와 ESP32 컴파일은 실제 보드 시험을 대체하지 않는다.
PSRAM 최대 사용량·측정 지연·소음/진동 물리 교정·실제 TLS·전원 차단 중 LittleFS/NVS·장기 플래시 수명·대량 장치 시험은 현장에서 추가해야 한다.
원시 음향에는 주변 대화가 포함될 수 있으므로 현장 고지·접근 통제·보관 정책을 확인한 뒤 요청 기능을 활성화한다.
