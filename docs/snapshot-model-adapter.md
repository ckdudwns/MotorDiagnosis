# 단건 모델 추론 연결부 — 3단계

## 현재 구현 범위

교체 모델 파일과 입력·출력 규격은 아직 전달되지 않았다. 따라서 **운영용 모델 로더나 실제 예측 모델을 추가하지 않았다.**
현재 `app.py`는 모델을 전달하지 않으며 새 자료는 입력 준비 후 `waiting_model`로 남는다.
RF66 로딩·자동 추론은 계속 중지되고, 보드의 이상 상태를 서버 모델 판정으로 대체하지 않는다.

이번 단계는 향후 검토된 어댑터를 `create_server(..., snapshot_model=adapter)`에 명시적으로 전달할 때 사용할
공통 연결 계약, 비동기 작업, 결과 저장 및 조회를 구현한다. 파일 경로·환경변수·HTTP 요청으로 임의의 모델이나
Python 모듈을 로드하는 기능은 없다. 테스트 전용 예측 함수는 `tests/`에만 있으며 앱에 기본 모델로 포함하지 않는다.

## 처리 흐름

```text
원본 검증 → 원본과 선택된 모델 작업을 함께 커밋 → ACK
    ↓ 별도 입력 준비 작업
queued → 샘플/해시 재검증 → XYZ g 입력 준비
    ├─ 수신 시 모델 배정 없음 → waiting_model
    ├─ 입력 품질 불량 → unavailable
    └─ 수신 시 모델 배정 있음 → queued_inference
            ↓ 별도 추론 작업 (수신 DB 잠금 밖에서 계산)
          원본·준비 입력·모델 계약 재확인 → 모델 전용 전처리/추론
            ├─ 유한 점수 → 명시된 임계값·비교 연산 → completed
            └─ 오류/유효하지 않은 출력/기한 초과 → unavailable
```

정상 정기, 이상 진입, 이상 정기, 정상 복귀 보고 모두 같은 경로를 사용한다.
단건마다 독립적으로 처리하며 보드 카운터·이전 12개 기록·RF66 연속 3구간 정책을 누적하지 않는다.
개별 `analysis.affectsAlerts: false`는 추론 함수가 직접 알림을 보내지 않는다는 뜻이다.
저장된 결과를 별도 [단건 사건·알림 처리기](snapshot-events.md)가 받아 운영 모드에 맞춰 처리한다.
기존 통계 점수·RF66 이력은 변경하지 않는다. GET 최상위 `affectsAlerts`는 현재 모델이 설정되고
`eventPolicy.mode=alerts`일 때만 true이며, 실제 발송은 최신 입력·사건 상태·알림 정책 검사에 따른다.

## 명시적 어댑터 계약

`motor_diagnosis.snapshot_model.SnapshotModelAdapter(metadata, predict)`로 구성한다.
`metadata`는 아래 키만 허용하며 구성 후 복사·고정한다.

| 키 | 의미 |
| --- | --- |
| `contractId` | `single-snapshot-anomaly-v1` |
| `modelId` | 교체 모델의 식별자 |
| `modelVersion` | 실제 모델을 재현할 수 있는 불변 버전, 실제 파일 해시 사용 권장 |
| `preprocessingVersion` | 특징 계산·정규화·점수 계산을 포함한 어댑터 전처리 버전 |
| `inputContract` | 아래의 공통 입력 준비 계약 전체 |
| `scope` | 적용할 `deviceId`, `siteId`, `assetId`의 정확한 조합 하나 |
| `scoreType` | 점수 의미. 예: 재구성 오차 또는 이상 클래스 확률. 이번 코드에서 임의 지정하지 않음 |
| `threshold` | 해당 모델 검증으로 결정한 유한 수치. 기본 임계값 없음 |
| `comparison` | `>`, `>=`, `<`, `<=` 중 하나. 해당 조건을 만족하면 이상 후보 |

공통 입력 준비 계약은 `snapshot_model.INPUT_CONTRACT`와 일치해야 한다.

- `adapterId`: `adxl345-xyz-g-unmodified-v1`
- `sourceProfileId`: `adxl345-800hz-xyz-counts-v1`
- `shape`: `[512, 3]`, `axes`: `X, Y, Z`, `unit`: `g`
- `sampleRateHz`: `800`, `gPerCount`: `0.0039`, `meanRemoved`: `false`

이는 **학습 모델 자체의 최종 입력 텐서 규격이 아니다.** 어댑터가 이 원시 구간으로 학습 시와 동일한
특징 추출·전처리를 수행해야 한다. 최근 12개 측정값이 필요한 모델은 이 단건 계약에 그대로 연결할 수 없다.
서버가 없는 이력을 만들어 채우거나 수집 간격을 5초로 간주하지 않는다.

`predict(prepared, context)`에는 복사본이 전달된다. `prepared.values`가 실제 `[512,3]` 가속도 값이다.
`context`에는 장치·사이트·설비·부팅 ID, 구간 번호, 측정 시각, uptime만 전달한다.
보드의 `ANOMALY_ACTIVE` 보고·카운터는 정답 라벨이나 모델 입력으로 전달하지 않는다.

출력은 둘 중 하나다.

- `{"score": 유한한_숫자}`: 서버가 고정한 임계값·비교 연산으로 bool 판정을 계산한다.
- `{"unavailableReason": "대문자_사유_코드"}`: 점수·판정 없이 분석 불가로 기록한다.

문자열 숫자, bool 점수, NaN/Infinity, 빠진 점수, 임의의 `verdict`나 추가 필드는 거부한다.
점수 0과 임계값 경계도 정확히 보존한다. 모델 예외 내용·경로·자격증명은 결과에 노출하지 않는다.

`bindingId`는 **메타데이터 전체의 SHA-256**이다. 모델 파일 자체의 해시 검증을 대신하지 않는다.
실제 어댑터를 제공할 때는 모델 파일 무결성, 의존성, 전처리/추론 일치성을 별도로 확인해야 한다.
모델/전처리/점수 의미/임계값을 변경하면 불변 버전과 연결 ID도 변경해야 한다.

## 저장·재시작·모델 변경

- DB 스키마 1→2에서 `snapshot_inference_jobs`, 2→3에서 사건 작업·사건 저장 테이블을 추가한다.
  원본과 기존 결과는 그대로 두며 이전 자료에 사건 작업을 소급 배정하지 않는다.
- 모델 배정은 **신규 수신 트랜잭션에서만** 수행한다. ACK 재전송·서버 재시작·모델 연결은 과거 자료의 재판정 사유가 아니다.
- 준비 완료 전에는 모델을 호출하지 않는다. 입력 품질 불량이면 배정 작업도 종료한다.
- 최초 배정된 모델 계약을 작업에 기록한다. 같은 계약으로 재시작하면 미완료 작업을 계속 처리한다.
- 다른 버전으로 시작하면 이전 버전의 작업을 인계하지 않는다. 원래 어댑터를 공급하거나 추후 명시적 재처리 절차를 마련해야 한다.
- 완료 결과는 모델 교체 후에도 덮어쓰지 않는다. 이전 모델 없는 `queued`/`waiting_model` 자료도 자동 배정하지 않는다.
- 추론 작업에는 60초의 실행 권한과 고유 토큰이 있다. 계산 중에는 SQLite 쓰기 잠금이나 수신 경로 잠금을 유지하지 않는다.
- 실행 권한이 만료된 미완료 작업은 같은 모델 작업자가 재획득할 수 있다. 오래된 토큰으로 새 결과를 덮어쓸 수 없다.
- 커밋 실패/비정상 종료 후 계산은 재실행될 수 있다. **계산 1회 보장이 아니라 확정 결과 중복 저장 방지**이며, 최대 3번 실제 계산 후 회복 불가 작업은 종료한다.
- 모델 오류·잘못된 출력은 자동 반복하지 않고 `unavailable`로 확정한다. `MODEL_EXECUTION_FAILED`, `MODEL_OUTPUT_INVALID`,
  `SNAPSHOT_INPUT_INTEGRITY_FAILED`, `INFERENCE_DEADLINE_EXCEEDED`, `INFERENCE_RETRY_EXHAUSTED`를 구분한다.
- 실행 권한은 Python 함수를 강제 종료하는 타이머가 아니다. 실제 어댑터는 실행 시간 제한·취소를 구현해야 한다.
  끝없이 멈춘 호출은 해당 추론 작업자를 점유하나, 수신과 입력 준비는 별도 작업에서 계속된다.
  종료 시 추론 작업자는 최대 2초 대기하고, 이후 반환하더라도 닫힌 DB에 결과를 기록하지 않는다.
- 백업에 원본·준비 결과·모델 배정·추론 결과가 같은 DB로 포함된다. 이전 코드(스키마 1 전용)로 돌아가려면
  마이그레이션 이전 백업을 사용해야 하며, 코드만 되돌리는 다운그레이드는 지원하지 않는다.

## 결과 조회·운영 점검

기존 인증된 `GET /api/devices/{deviceId}/periodic-snapshots`에 포함한다.

- 최상위 `configuredModel`은 현재 조회 범위에 명시적으로 연결한 어댑터 계약이다. 없으면 null이다.
- `inferenceEnabled`는 현재 해당 범위의 어댑터 설정 여부이며, 모델 없는 기본 앱에서는 false다.
- 항목별 `inferenceJob`은 상태, 연결 ID, 시도 횟수, 해당 작업을 처리할 어댑터가 현재 있는지를 표시한다.
- 완료된 `analysis`에는 점수, 임계값, 비교 조건, 판정, 모델 버전과 `inference` 처리 이력이 들어간다.
- `analysis.inference`에는 전체 모델 계약, 원본 digest, 시도 번호, 처리 시작/완료 시각, 처리 시간이 기록된다.
- 정상 후보는 해당 단건의 모델 결과이며 장비 정상 확정·현재 상태 보장이 아니다.
- `operations inspect`는 입력 준비 지연과 추론 대기 지연을 구분한다. 추론 배정 후 120초 이상 대기는 `INFERENCE_BACKLOG`다.
- DB만 읽는 운영 점검은 현재 프로세스의 어댑터 설정을 확정할 수 없다. 저장된 작업이 있으면
  `inferenceEnabled: null`, `modelStatus: runtime_not_observed`로 표시한다. 현재 설정은 GET API로 확인한다.

## 검증과 남은 연결 작업

```text
python -m unittest tests.test_snapshot_inference tests.test_snapshot_preparation tests.test_periodic_snapshots tests.test_edge_state_snapshots -q
```

테스트 더블로 독립 추론, 경계값, 오류, 상태 보고와 모델 판정 분리, 수신/ACK 비차단,
중복/재시작/경쟁 작업자, 만료 토큰 차단, 커밋 실패, 종료, 모델 버전 고정, DB 이전·백업 복원을 확인한다.
이 검증은 실제 모델 정확도·하드웨어 성능 검증이 아니다.

실제 모델이 준비되면 모델 파일 및 해시, 학습 측 전처리 코드, 입력 계약, 점수 의미·임계값·비교 조건,
동일 입력에 대한 정답 출력 샘플을 받아 어댑터를 구현한다. 이후 제한 시간·추론 비용을 검증하고 배포 설정을 추가한다.
웹은 [단건 수신·판정 화면](periodic-single-snapshots.md#웹-화면)으로 연결했다.
사건·알림은 [별도 운영 정책](snapshot-events.md)으로 연결했다. 과거 자료 자동 재판정·알림 재발송은 하지 않는다.
